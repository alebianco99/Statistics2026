Homework 2: From Wallet Seed to Ethereum Address — Hashing, Key Derivation & Cryptographic Primitives

1. Theoretical Taxonomy of Cryptographic Concepts

To understand the architecture of modern cryptocurrency wallets (such as MetaMask, Rabby, Exodus, or Rainbow), we must distinguish between fundamental cryptographic operations:

  • Key Generation vs. Key Derivation: Key Generation creates a primary source of high-entropy randomness (e.g., a 128-bit or 256-bit entropy buffer). Key Derivation pseudorandomly computes child keys from a single master seed using deterministic hash-based functions (PBKDF2, HMAC-SHA512).
  • Public-Key Cryptography (Asymmetric): Utilizes mathematical one-way trapdoor functions (such as discrete logarithms on elliptic curves) to create paired keys: a Private Key for signing transactions and a Public Key for signature verification.
  • Cryptographic Hashing: One-way deterministic functions mapping arbitrary-length inputs to fixed-size output strings. They provide pre-image resistance, second pre-image resistance, and collision resistance.
  • Checksums & Encoding: Encoding represents binary data in human-readable formats (e.g., Hexadecimal or Base58). A Checksum appends redundancy bits or case variations to detect human transcription errors or typos before sending funds.

2. Chronological & Historical Context

The Ethereum wallet pipeline does not rely on a monolithic protocol created at a single moment; rather, it combines decades of evolutionary cryptographic standards:

  • 1977 — RSA (Rivest-Shamir-Adleman): The first widely commercialized public-key cryptosystem, based on prime factorization integer hardness.
  • 2001 — SHA-2 / SHA-512: Standardized by NIST, based on the Merkle–Damgård construction, widely used in Bitcoin and seed derivation protocols.
  • 2012 — BIP-32: Proposed Hierarchical Deterministic (HD) wallets, allowing tree-structured key generation from a single seed.
  • 2013 — BIP-39: Standardized human-friendly 12-to-24 word mnemonic sentences mapped to binary seeds via PBKDF2.
  • 2014 — BIP-44: Established multi-account, multi-coin derivation path structures (e.g., m/44'/60'/0'/0/0 for Ethereum).
  • 2015 — SHA-3 (NIST FIPS 202): Standardized cryptographic hash family based on the Keccak sponge construction.
  • 2016 — EIP-55: Ethereum proposal introducing mixed-case checksum encoding to prevent mistyped address transfers.

Keccak-256 vs. Standard SHA3-256

A critical technical distinction exists between Keccak-256 (used by Ethereum) and NIST SHA3-256. While both use the same underlying permutation engine developed by Guido Bertoni, Joan Daemen, Michaël Peeters, and Gilles Van Assche, they differ in their domain separation padding:

Keccak-256 Padding Byte: 0x01  |  NIST SHA3-256 Padding Byte: 0x06

Ethereum adopted Keccak-256 prior to the finalization of the NIST standard in FIPS 202. Consequently, hashing the same input with Keccak-256 and NIST SHA3-256 yields completely different output hashes.

4. Statistical Exploration & System Modularity

Statistical Uniformity and Bit Independence

The security of the wallet architecture relies on the statistical independence and uniform distribution of each layer:

  • Entropy to Seed (PBKDF2): Applying 2048 rounds of HMAC-SHA512 stretches 128 bits of initial randomness into a 512-bit seed, eliminating short-word structural patterns in natural language mnemonics.
  • ECDSA Key Uniformity: The private key space consists of integers $k \in [1, n-1]$ where $n \approx 1.158 \times 10^{77}$. The point multiplication $Q = k \cdot G$ maps uniformly across the field.
  • Hash Uniformity: Keccak-256 exhibits optimal pseudo-randomness, where flipping a single bit in the public key alters on average 50% of the bits in the output hash.

Why Use Multiple Primitives Instead of One Single Algorithm?

A secure blockchain ecosystem requires distinct cryptographic properties that no single algorithm can fulfill simultaneously:

  • BIP-39 / BIP-32 / BIP-44 (Key Management): Provides human usability (memorizable words) and hierarchical key tree derivation, allowing a user to back up a single phrase while generating millions of independent addresses.
  • secp256k1 (Asymmetric Cryptography): Provides digital signatures (ECDSA) to prove ownership without disclosing the private key.
  • Keccak-256 (Cryptographic Hashing): Shortens 65-byte public keys to 32-byte hashes, destroying algebraic homomorphism to prevent public-key-based lattice or quantum exposure until funds are actually spent.
  • EIP-55 (Error Detection / Checksum): Protects against human mistranscription errors during wallet transactions without adding protocol-level payload overhead.
